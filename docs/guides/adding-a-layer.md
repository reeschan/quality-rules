# 別の言語の層を足す手引き

このリポジトリには、Python など TypeScript 以外の言語のパッケージの雛形は置いていません。ここに書くのは、その言語のパッケージを足すときの形だけです。

## 共通の規約の本文は同じまま使う

共通の**層**の**規約**（NAME・GEN・FIX・REUSE・CONCERN・CMT・UX・E2E）の本文は、`packages/rules/conventions/<ID>.md` にあり、言語に依らない説明だけを持ちます。例のコードは持ちません。新しい言語のパッケージは、この本文をそのまま同梱します。言語ごとに書き直したり、言い換えたりしません。

## 例はその言語で書く

規約の「悪い例」「良い例」は、言語のパッケージが持ちます。TypeScript のパッケージでは `packages/typescript/conventions/examples/<ID>.md` に、共通の規約と同じ ID で置いています。新しい言語では、同じ ID・同じ並びで、例のコードをその言語で書いたファイルを用意します。

その言語だけの**規約**（TYPE・UNIT・STYLE のような分類）は、そのパッケージの `conventions/` に、欄（ID・層・束・理由・確かめる問い・機械検査・機械では拾えない残り）を揃えて書きます。

## カタログの形は言語に依らない

パッケージの中身（カタログ）は、次の形です。言語が変わっても同じです。

- `packs/<束>.json`: **束**の説明と、**ルール**の一覧。各ルールは `id`・`tool`・`description`・`added`（足された版）・既定のオプション・道具ごとの設定の断片を持つ。
- `conventions/<ID>.md`: **規約** 1 項目 1 ファイル。先頭に `id`・`layer`・`pack`・`added`・`check`（受け持つルール）を書く。
- `package.json` の `qualityRules` 欄: `packs`・`conventions`・`rules` の場所。
- 規約を受け持つ**ルール**は、同じ**束**に入れる。

道具（lint など）の設定の断片は、その言語の道具の名前で書きます。CLI の `list`・`sync`・`check` は、カタログの形を読むだけなので、言語を意識しません。

## 足す手順

1. 言語のパッケージを作り、`qualityRules` 欄で束・規約・ルールの場所を示す。
2. 共通の規約の本文を同梱し、例をその言語で書く。
3. その言語の道具の束（`packs/*.json`）と、固有の規約を書く。
4. 利用者は、マニフェストの `packages` と `packs` にそのパッケージを書き、`quality-rules sync` を走らせる。
